# AI UI — رابط فارسی چت و سشن‌های Codex

برنامه‌ای محلی با رابط راست‌به‌چپ برای چت، ضبط ویس و ادامهٔ گفتگوهای پروژه‌ای Codex.

## امکانات

- نمایش سشن‌های محلی بر اساس پروژه و ادامهٔ همان گفتگو با ابزارهای Codex
- نمایش پیشرفت کار، درخواست اجازه، سؤال‌های Codex و توقف اجرا
- آرشیو، بازیابی و حذف گفتگو با تأیید صریح
- چت عادی با ارائه‌دهندهٔ سازگار با OpenAI Responses API
- ضبط ویس با تایمر و پخش قبل از ارسال
- ضمیمهٔ تصویر، PDF، متن و Excel
- کادر ارسال کوچک، اسکرول مستقل گفتگو و نمایش مصرف توکن
- Enter برای ارسال؛ Shift+Enter برای خط بعد

## پیش‌نیازها

- Node.js نسخهٔ ۲۰ یا بالاتر و npm
- Codex نصب‌شده و ورود به حساب برای سشن‌های پروژه‌ای
- فایل `~/.codex/config.toml` با مدل و ارائه‌دهندهٔ دلخواه
- Chrome یا Edge و دسترسی میکروفون برای ویس

راهنمای رسمی: [تنظیمات Codex](https://learn.chatgpt.com/docs/config-file/config-reference) و [App Server](https://learn.chatgpt.com/docs/app-server).

## نصب و اجرا

```sh
git clone https://github.com/codeup70/ai-ui.git
cd ai-ui
npm ci
```

فایل `.env.example` را به `.env` کپی کنید و در صورت نیاز تنظیماتش را تغییر دهید.

```sh
npm start
```

آدرس: `http://localhost:3000`. در ویندوز پس از نصب وابستگی‌ها می‌توانید از `start.bat` استفاده کنید.

این برنامه برای اجرای شخصی روی رایانهٔ خودتان است؛ سرور روی `127.0.0.1` گوش می‌دهد و سرویس چندکاربرهٔ اینترنتی نیست.

## تنظیمات

| متغیر در `.env` | کاربرد |
| --- | --- |
| `PORT` | پورت؛ پیش‌فرض `3000` |
| `CODEX_HOME` | پوشهٔ تنظیمات و سشن‌های Codex؛ پیش‌فرض `~/.codex` |
| `CODEX_CONFIG_PATH` | فایل تنظیمات جایگزین برای چت عادی؛ محل سشن‌ها را تغییر نمی‌دهد |
| `CODEX_BIN` | مسیر فایل اجرایی Codex، اگر تشخیص خودکار یا PATH کافی نیست |
| `CLAUDE_BIN` | مسیر فایل اجرایی Claude Code در صورت نیاز؛ نصب موجود به‌طور خودکار پیدا می‌شود |
| `OPENAI_API_KEY` | کلید چت عادی، در صورت نیاز ارائه‌دهنده |

برنامه از `model`، `model_reasoning_effort`، `model_provider` و پروفایل پیش‌فرض Codex استفاده می‌کند. ارائه‌دهندهٔ چت عادی باید Responses API را پشتیبانی کند. `base_url`، `env_key`، `experimental_bearer_token` و هدرهای تنظیم‌شده پشتیبانی می‌شوند. کلیدها روی سرور می‌مانند.

ورود به حساب Codex برای سشن‌های پروژه‌ای استفاده می‌شود؛ لزوماً کلید لازم برای چت عادی را فراهم نمی‌کند. هر کاربر باید احراز هویت ارائه‌دهندهٔ خودش را تنظیم کند. هیچ کلید، حساب یا تنظیمات شخصی همراه مخزن نیست.

پس از تغییر تنظیمات یا کد سرور، برنامه را دوباره اجرا و صفحه را تازه کنید.

## سشن‌های پروژه‌ای

سشن‌های همین رایانه با رابط رسمی `codex app-server` خوانده می‌شوند. ارسال پیام، همان شناسهٔ سشن و مسیر پروژه را ادامه می‌دهد. تنظیمات مجوز و sandbox دور زده نمی‌شوند و پایگاه دادهٔ Codex مستقیماً ویرایش نمی‌شود.

تاریخچه هر دو ثانیه و فهرست سشن‌ها هر ۳۰ ثانیه تازه می‌شود. چت‌های عادی مرورگر جدا نگه داشته می‌شوند. سشن‌های دستگاه‌های دیگر یا تاریخچهٔ صرفاً ابری دریافت نمی‌شوند.

ابتدا کار فعال یک سشن را در برنامهٔ دسکتاپ تمام کنید و سپس اینجا ادامه دهید؛ این رابط یک پردازش app-server جداگانه دارد. درخواست ابزارهای مخصوص کلاینت که پشتیبانی نمی‌شوند با خطای واضح متوقف می‌شوند.

آرشیو تاریخچه را برای بازیابی نگه می‌دارد. از بخش «آرشیوشده‌ها» می‌توانید گفتگو را بازیابی کنید. حذف سشن پس از تأیید، تاریخچهٔ آن و سشن‌های فرزندش را دائماً حذف می‌کند. حذف چت عادی و پاک‌کردن پیام‌ها هم تأییدیه دارند.

## اتصال Claude Code

اگر `claude` در ترمینال شما کار می‌کند، برنامه از همان نصب، ورود و تنظیمات کاربر و پروژه استفاده می‌کند. نصب SDK با `npm install` انجام می‌شود؛ اطلاعات ورود وارد مرورگر یا مخزن نمی‌شود. روش احراز هویت و مصرف همان تنظیمات ترمینال است، از جمله متغیرهای API در صورت تنظیم بودن.

سشن‌های محلی Claude با نام پروژه در فهرست ظاهر می‌شوند. برای شروع، «گفتگوی تازه» را بزنید، دستیار Claude یا Codex را انتخاب کنید. مسیر پروژه اختیاری است؛ برای چت عادی آن را خالی بگذارید. فضای کاری گفتگوهای عادی به‌صورت خودکار در `~/.ai-ui/conversations` ساخته می‌شود. فهرست مدل‌ها کنار کادر پیام از دستیار انتخاب‌شده دریافت می‌شود؛ «پیش‌فرض گفتگو» تنظیم جاری را حفظ می‌کند. انتخاب مدل روی پیام‌های بعدی اثر دارد و هر پیام صف، مدل زمان ارسال خودش را نگه می‌دارد.

ادامهٔ گفتگو همان شناسه و پوشهٔ سشن را به SDK رسمی می‌دهد. درخواست اجازهٔ ابزار و سؤال‌های Claude داخل چت نمایش داده می‌شوند؛ حالت دورزدن مجوزها فعال نمی‌شود. «توقف کار» اجرای Claude را متوقف و صف را مکث می‌کند. سشن را هم‌زمان در ترمینال و این رابط ادامه ندهید. گفتگوی تازه تا اولین ارسال فقط در حافظهٔ سرور است؛ تاریخچهٔ ارسال‌شده را خود Claude ذخیره می‌کند.

آرشیو Claude فقط فیلتر همین UI است و در فایل محلی `.claude-ui-state.json` نگه داشته می‌شود. حذف پس از تأیید نام گفتگو، از SDK رسمی انجام می‌شود. این فایل، اطلاعات ورود و تاریخچه‌های شخصی در گیت قرار نمی‌گیرند.

## حالت دسترسی

حالت‌های کنار کادر پیام با الگوگیری از [CloudCLI](https://github.com/siteboon/claudecodeui) به تنظیمات بومی هر اجراکننده متصل‌اند.

| حالت | Codex | Claude |
| --- | --- | --- |
| Default | محدودهٔ پروژه، درخواست تأیید برای خروج از محدوده | مجوزهای استاندارد |
| Accept Edits | محدودهٔ پروژه، بدون درخواست تأیید؛ عملیات ممنوع رد می‌شود | ویرایش فایل خودکار؛ فرمان‌های حساس ممکن است تأیید بخواهند |
| Full Access | بدون sandbox و بدون درخواست تأیید ابزار | bypassPermissions |
| Auto | ارائه نمی‌شود | تصمیم‌گیری مدل دربارهٔ مجوزها؛ وابسته به پشتیبانی مدل و حساب |
| Plan | ارائه نمی‌شود | بررسی و برنامه‌ریزی پیش از اجرا |

Codex در Default از workspaceWrite/on-request و در Accept Edits از workspaceWrite/never استفاده می‌کند. مسیر نوشتن از پوشهٔ اصلی گفتگو گرفته می‌شود؛ شبکه خاموش است. پوشه‌های موقت استاندارد و مسیرهای محافظت‌شده تابع سیاست Codex هستند. Full Access فقط با انتخاب صریح فعال می‌شود و محدودیت سیستم‌عامل یا سیاست سازمانی را تغییر نمی‌دهد.

انتخاب هر گفتگو در مرورگر ذخیره می‌شود و حالت‌های بومی از پیام بعدی اعمال می‌شوند؛ اجرای جاری باید تمام یا متوقف شود. سؤال‌های کاربر و تأیید خروج از Plan در Claude از hook تعاملی عبور می‌کنند، حتی در Auto و Full Access. خطای اعمال سیاست یا عدم پشتیبانی اجراکننده نمایش داده می‌شود؛ حالت ضعیف‌تر به‌طور پنهان جایگزین نمی‌شود.

برای حفظ سطح مجوز قبلی، انتخاب‌های قدیمی با برچسب «قدیمی» باقی می‌مانند و خودکار به مجوز بالاتر تبدیل نمی‌شوند. برای استفاده از رفتار جدید، یکی از حالت‌های بومی را انتخاب کنید. حالت‌های قدیمی تنها برای سازگاری نگه داشته شده‌اند.

پس از این به‌روزرسانی، سرور را دوباره اجرا و صفحه را رفرش کنید. تغییر کد، مجوز اجرای همین نشست عامل یا برنامهٔ دسکتاپ دیگری را عوض نمی‌کند.

## جست‌وجو و دانلود گفتگو

«وضعیت و مصرف» نام گفتگو، مجموع توکن‌های ثبت‌شده، ورودی، خروجی و کش همان گفتگو را حتی در حالت بیکار نشان می‌دهد. برای Codex آخرین شمارندهٔ تجمعی از فایل تاریخچهٔ معرفی‌شده توسط app-server فقط خوانده می‌شود؛ برای Claude مصرف پیام‌های API تاریخچه با حذف رکوردهای تکراری جمع می‌شود. زیرسشن‌های Claude در این جمع نیستند. نبود اطلاعات مصرف با «ثبت نشده» مشخص می‌شود. این اعداد مجموع تاریخچهٔ در دسترس‌اند، نه هزینهٔ مالی یا اندازهٔ context؛ کپی سشن ممکن است آمار تاریخچهٔ مبدأ را هم داشته باشد. پس از به‌روزرسانی، سرور را دوباره اجرا و صفحه را تازه کنید.

دکمهٔ «کپی و ادامه» بالای گفتگو یک سشن مستقل با تاریخچهٔ قبلی می‌سازد. عنوان و مدل ادامه را در پنجره انتخاب کنید، سپس پیام بعدی را در کپی بفرستید. Codex از `thread/fork` و Claude از `forkSession` استفاده می‌کند؛ چت محلی نیز کپی مستقل پیام‌ها دارد. انتخاب مدل در همان ارائه‌دهنده است؛ انتقال بین Codex و Claude انجام نمی‌شود. فایل‌های پروژه و ضمیمه‌ها مشترک‌اند؛ این قابلیت نسخهٔ جدا از پوشهٔ پروژه یا تاریخچهٔ undo فایل‌ها نمی‌سازد. صف پیام‌ها و درخواست‌های در انتظار منتقل نمی‌شوند. برای سشن در حال اجرا ابتدا منتظر پایان بمانید. پس از نصب این تغییر، سرور را دوباره اجرا و صفحه را رفرش کنید.

دکمهٔ مداد کنار هر گفتگو، پنجرهٔ ویرایش عنوان را باز می‌کند. عنوان تا ۱۲۰ نویسه پذیرفته می‌شود؛ عنوان چت محلی در مرورگر و عنوان سشن‌های Codex/Claude از طریق API رسمی همان اجراکننده ذخیره می‌شود. عنوان پیش‌نویس Claude با اولین پیام به سشن منتقل می‌شود. برای فعال‌شدن مسیر جدید ذخیرهٔ عنوان، سرور را دوباره اجرا و صفحه را رفرش کنید.

از دکمهٔ «جست‌وجوی پیام‌ها» بالای گفتگو، متن همهٔ پیام‌های همین گفتگو یا همهٔ گفتگوهای محلی، Codex و Claude را جست‌وجو کنید. آرشیو اختیاری است. تاریخچهٔ سشن‌های بازنشده نیز خوانده می‌شود؛ نتیجه‌ها به پیام مربوط می‌روند. تفاوت حروف ی/ي و ک/ك در جست‌وجو نادیده گرفته می‌شود. خطای خواندن هر منبع با هشدار نتیجهٔ ناقص نمایش داده می‌شود. حداکثر ۳۰۰ نتیجه نمایش داده می‌شود؛ برای نتیجه‌های بیشتر عبارت را دقیق‌تر کنید.

«دانلود گفتگو» متن تمام پیام‌های گفتگوی انتخاب‌شده را به HTML، Markdown یا JSON ذخیره می‌کند. HTML مستقل و متن آن escape شده است. نام ضمیمه‌ها، در صورت وجود در تاریخچه، درج می‌شود؛ فایل و صوت ضمیمه نمی‌شوند. برای سشن‌های پروژه‌ای، تاریخچه هنگام دانلود دوباره از سرور خوانده می‌شود. پاسخ در حال اجرا ممکن است ناقص باشد.

## ویس و فایل‌ها

ویس تا پنج دقیقه ضبط و قبل از ارسال قابل پخش و حذف است. صوت در IndexedDB مرورگر ذخیره می‌شود؛ فایل‌های قدیمی‌تر از ۲۴ ساعت هنگام بازکردن بعدی برنامه پاک می‌شوند. تشخیص گفتار هم‌زمان در پس‌زمینه انجام می‌شود و ممکن است از سرویس آنلاین سازندهٔ مرورگر استفاده کند. فقط متن ویس پس از ارسال به ارائه‌دهندهٔ چت فرستاده می‌شود.

حداکثر پنج ضمیمه در هر پیام: تصویر PNG/JPEG/WebP تا ۸ مگابایت، PDF تا ۳۲ مگابایت، متن/کد تا ۱ مگابایت و Excel تا ۸ مگابایت. پیش‌نمایش Excel تا ۲۰۰ ردیف در هر شیت است. PDF در سشن‌های Codex با مسیر محلی معرفی می‌شود؛ خواندن آن تابع ابزارها و مجوزهای Codex است.

چت‌های عادی در localStorage و ضمیمه‌ها در `uploads/` ذخیره می‌شوند. محتوای ضمیمه‌ها هنگام استفاده در گفتگو در اختیار ارائه‌دهنده قرار می‌گیرد. فایل `.env`، آپلودها، تاریخچه‌ها و حافظهٔ شخصی عامل نباید وارد گیت شوند.

## تست‌ها

```sh
npm test
```

تست‌های واحد به حساب واقعی نیاز ندارند و هیچ سشن واقعی را حذف نمی‌کنند.

تست‌های اختیاری فقط‌خواندنی با Codex نصب‌شده و سشن محلی:

```sh
npm run test:codex
npm run test:browser
```

تست مرورگر به Chrome/Chromium نیاز دارد؛ در صورت نیاز مسیر آن را با `CHROME_BIN` مشخص کنید. این تست‌ها پیامی به مدل نمی‌فرستند.
